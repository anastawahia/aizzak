## 0. القيود

### 0.1 لماذا لا يمكن البدء قبل الباك-اند

أنواع الواجهة **مولَّدة من عقد الخادم**، لا مكتوبة يدويًّا:

```
openapi.json  ──(npm run gen:api)──▶  src/api/schema.d.ts  ──▶  request() المُنمَّط
```

و`request` في [`src/api/http.ts`](../../web_app/src/api/http.ts) يستنبط المسار والوسائط والجسم والاستجابة من `paths` في `schema.d.ts`. ⇒ **نداءٌ إلى `/api/v1/spaces` لا يجتاز `tsc` قبل أن يوجد المسار في `openapi.json`.**

وسلسلة البناء تفرض ذلك:

```bash
npm run build   # = gen:api → test:rag-contract → typecheck → vite build
```

**الترتيب الملزِم:** أغلِق الباك-اند ⇒ صدّر `openapi.json` الجديد إلى جذر `web_app` ⇒ `npm run gen:api` ⇒ ابدأ.

### 0.2 حارس العقد

[`scripts/verify-rag-contract.mjs`](../../web_app/scripts/verify-rag-contract.mjs) يتحقّق من وجود المسارات والوسائط قبل كلّ بناء. يجب أن يكسب تأكيدات الوحدات — **وإلّا مرّ نقصٌ في العقد صامتًا حتّى زمن التشغيل.**

### 0.3 الاتّجاه

التطبيق عربيّ RTL. في `direction: rtl` **أوّل ابنٍ في DOM يُرسم أقصى اليمين**. مخطّطات §3 مكتوبة بالترتيب البصريّ؛ ترتيب DOM معكوس.

## 1. النموذج كما يراه المستخدم

```
صفحة الوحدات
   └── وحدة  (1 GiB)
         ├── ملفّات الوحدة        ← اللوحة اليمنى · يراها كلّ محادثات الوحدة
         └── محادثات الوحدة       ← اللوحة اليسرى
               └── تثبيت           ← تضييق اختياريّ داخل ملفّات الوحدة
```

**ثلاث جملٍ يجب أن تصل للمستخدم من الواجهة نفسها، بلا شرح:**

1. الملفّ يخصّ **الوحدة**، لا المحادثة — رفعه من أيّ محادثة يُظهره في كلّ محادثات الوحدة.
2. المحادثات **لا ترى** ملفّات وحدةٍ أخرى، ولا تُسرد عندها.
3. **التثبيت اختياريّ:** بلا تثبيت يجيب الوكيل من كلّ ملفّات الوحدة؛ بتثبيتٍ يجيب من المُثبَّت وحده.

## 3. الخطوات

### ف‑١ · المسارات

```
/rag                       →  SpacesHome    صفحة الوحدات
/rag/s/:spaceId            →  SpaceView     يحوّل إلى آخر محادثة
/rag/s/:spaceId/:convId    →  SpaceView     الشاشة الثلاثيّة
```

`/rag/:agentId` القديم يصير **تحويلًا** إلى `/rag` — بنفس نمط `SummarizeRoute` الموجود في [`App.jsx`](../../web_app/src/App.jsx)، فالإشارات المرجعيّة القديمة لا تنكسر بشاشةٍ بيضاء.

> **تنبيه:** بيانات المحادثات القديمة مُسِحت في 2026‑08‑16. أيّ معرّف محادثة محفوظٍ في متصفّح المستخدم لم يعد له وجود، والتحويل هو ما يمنع 404.

### ف‑٢ · `features/rag/api/spaces.ts` — جديد

```ts
listSpaces()            // + bytes_used · file_count · conversation_count
createSpace(name)
renameSpace(id, name)
deleteSpace(id)         // حذف متسلسل
```

ويُضاف `export * from './spaces';` إلى [`api/index.ts`](../../web_app/src/features/rag/api/index.ts).

### ف‑٣ · تمرير `spaceId` عبر الطبقة القائمة

| الدالّة | التغيير |
|---|---|
| `listRagFiles(spaceId)` | `query: { space_id, limit }` |
| `listKnowledgeDocuments(spaceId)` | `query: { space_id, limit }` |
| `listWorkspaceKnowledgeFiles(spaceId)` | تمرير إلى الاثنتين أعلاه |
| `uploadRagFile(spaceId, file)` | `space_id` في جسم `POST /files` |
| `listRagConversations(spaceId)` | `query: { space_id }` |
| `createRagConversation(spaceId, title)` | `space_id` في الجسم |
| `renameRagFile` · `deleteRagFile` · `reindexRagDocuments` | **بلا تغيير** — تعمل بالمعرّف |
| `listPinnedFileIds` · `pinRagFile` · `unpinRagFile` | **بلا تغيير** — الوحدة مستنتَجة من المحادثة خادمًا |

> **`spaceId` أوّل وسيط، لا أخير.** إضافته في الآخر بقيمة افتراضيّة تجعل نداءً منسيًّا يُصرَّف بنجاح ويقرأ الوحدة الخطأ. في الأوّل، كلّ موضع نداءٍ لم يُحدَّث **يسقط في `tsc`** — وهذا هو المطلوب.

### ف‑٤ · `SpacesHome` — صفحة الوحدات

أوّل ما يراه المستخدم عند فتح وكيل RAG.

```
┌────────────────────────────┐   ┌────────────────────────────┐
│  📁  main space            │   │  📁  عقود ٢٠٢٦             │
│  ٤ ملفّات · ٣ محادثات      │   │  ١٢ ملفًّا · ١ محادثة       │
│  ▓▓▓▓▓░░░░░  412 MB / 1 GB │   │  ▓▓▓▓▓▓▓▓▓░  0.94 / 1 GB   │
│                     ✏️  🗑️  │   │                     ✏️  🗑️  │
└────────────────────────────┘   └────────────────────────────┘
                    ┌──────────────┐
                    │  +  وحدة جديدة│
                    └──────────────┘
```

| العنصر | السلوك |
|---|---|
| البطاقة | هدف تنقّل ⇒ `/rag/s/:id` |
| شريط الحصّة | تحذيريّ فوق ٨٠٪ · حرِج فوق ٩٥٪ |
| ✏️ إعادة تسمية | نموذجٌ داخل البطاقة — **يوقف انتشار النقرة** وإلّا فُتحت الوحدة |
| 🗑️ حذف | `ConfirmModal` بنصٍّ صريح لا مواربة فيه |
| + وحدة | حقلُ اسمٍ ثمّ تنقّلٌ فوريّ إلى الوحدة الجديدة |

**نصّ تأكيد الحذف — حرفيًّا:**

> **حذف الوحدة «‹الاسم›» نهائيًّا؟**
> سيُحذف معها **‹ن› ملفًّا** و**‹م› محادثة** وكلّ فهرسها. **لا يمكن التراجع.**

الأعداد من `listSpaces()` — لا تُخمَّن ولا تُترك مبهمة. مستخدمٌ يحذف وحدةً وهو لا يعلم أنّها تحمل 12 ملفًّا هو خطأُ واجهةٍ لا خطأُ مستخدم.

منطق الإنشاء والتسمية والحذف و`ConfirmModal` **منقولٌ من `RagHome` الحاليّ** — الشيفرة موجودة ومجرَّبة، تُعاد توجيهها من المحادثات إلى الوحدات.

**«main space» لا تُنشئها الواجهة.** الخادم يوفّرها (خطّة الباك-اند §3.7). الواجهة تعرض ما يعود، وتعرض حالة فراغٍ فقط إن عاد فارغًا فعلًا.

### ف‑٥ · `SpaceView` — الشاشة الثلاثيّة

```
┌────────────┬──────────────────────┬────────────┐
│  محادثات   │      المحادثة        │   ملفّات    │
│            │                      │            │
│ + محادثة   │   ...الرسائل...      │ + رفع ملف  │
│ ▸ chat1    │                      │ 📄 file1 ✅📌│
│ ▸ chat2 ✓  │                      │ 📄 file2 ⏳ │
│ ▸ chat3    │  ┌────────────────┐  │ 📄 file3 ✅ │
│            │  │ اكتب رسالة...  │  │            │
│   🗑️        │  └────────────────┘  │ فهرسة·تلخيص│
└────────────┴──────────────────────┴────────────┘
   يسار              الوسط              يمين
```

| العمود | المكوّن | الحال |
|---|---|---|
| يمين — ملفّات | `WorkspaceFiles` | **موجود** · يكسب `spaceId` · **يحتفظ بالتثبيت** |
| وسط — محادثة | `RagConversation` | **موجود** · يفقد `<aside>` الحاليّ لصالح العمودين |
| يسار — محادثات | `ConversationsPanel` | **جديد** — منطقه من `RagHome` |

**التنقّل:**
- `/rag/s/:spaceId` بلا معرّف محادثة ⇒ افتح آخر محادثة (`updated_at` تنازليًّا)
- الوحدة فارغة ⇒ أنشئ محادثةً تلقائيًّا وانتقل إليها (لا شاشة فارغة كأوّل انطباع)
- الوحدة غير موجودة أو 404 ⇒ عُد إلى `/rag` برسالة

**تحميل البيانات:** `SpaceView` يجلب ملفّات الوحدة ومحادثاتها **مرّةً واحدة** ويمرّرهما للعمودين. جلبُ كلّ عمودٍ لنفسه يعني نداءين متكرّرين عند كلّ تنقّلٍ بين محادثتين في الوحدة نفسها.

### ف‑٦ · `WorkspaceFiles` — التغييرات

**البنية والتثبيت يبقيان.** ما يتغيّر:

| البند | من | إلى |
|---|---|---|
| مصدر البيانات | `listWorkspaceKnowledgeFiles()` | `listWorkspaceKnowledgeFiles(spaceId)` |
| الرفع | `uploadRagFile(file)` | `uploadRagFile(spaceId, file)` |
| عنوان اللوحة | «ملفّات مساحة العمل» | **«ملفّات الوحدة»** |
| شرح النطاق | «هذا النطاق يخصّ هذه المحادثة» | **«كلّ محادثات هذه الوحدة ترى هذه الملفّات»** |
| شرح التثبيت | — | **«بلا تثبيت يجيب الوكيل من كلّ ملفّات الوحدة»** |
| **جديد** | — | شريط الحصّة أعلى اللوحة + رفضٌ استباقيّ (§ف‑٧) |

**زرّ التثبيت 📌 يبقى كما هو** — لكن معناه صار أدقّ: تضييقٌ داخل ملفّاتٍ يراها المستخدم كلّها أصلًا، لا منحُ وصول. اجعل النصّ يقول ذلك.

### ف‑٧ · الحصّة في الواجهة

الخادم يرفض بـ`409 spaces.quota_exceeded`، لكن الرفض بعد رفع 900 MiB تجربةٌ سيّئة.

```
1. اعرض  bytes_used / 1 GiB  دائمًا أعلى لوحة الملفّات
2. قبل الرفع: لو  used + file.size > 1 GiB  ⇒ ارفض محلّيًّا وسمِّ الفائض
3. بعد كلّ رفعٍ أو حذف: أعد جلب  bytes_used  من الخادم — لا تحسبه محلّيًّا
```

**السطر ٣ ليس تزيّدًا:** الحساب المحلّيّ ينحرف عن الخادم عند رفعٍ من لسان تبويبٍ آخر أو حذفٍ متزامن، ومقياسُ حصّةٍ يكذب أسوأ من غياب المقياس. الخادم هو المرجع؛ الواجهة تعرض ما عاد منه.

الرفض المحلّيّ (السطر ٢) **تحسينٌ لا حارس** — الحارس الحقيقيّ هو الخادم.

### ف‑٨ · حارس العقد

في [`scripts/verify-rag-contract.mjs`](../../web_app/scripts/verify-rag-contract.mjs):

```
+ GET    /api/v1/spaces
+ POST   /api/v1/spaces
+ PATCH  /api/v1/spaces/{space_id}
+ DELETE /api/v1/spaces/{space_id}
+ requireParameter(GET /api/v1/files,                 'space_id', 'query')
+ requireParameter(GET /api/v1/conversations,         'space_id', 'query')
+ requireParameter(GET /api/v1/knowledge/documents,   'space_id', 'query')
+ حقل bytes_used في مخطّط الوحدة
```
