# §3.126 — ج‑2: إزالة حاويتَي `:latest` المستقلتين

**التاريخ:** 2026‑08‑05  
**الخطة:** [`containerised-test-harness-plan-v2.md`](../containerised-test-harness-plan-v2.md)  
**الخطوة:** ج‑2 فقط — حذف الحاويتين القديمتين، بلا صور أو حجوم أو إعادة تشغيل  
**الحصيلة:** ✅ مكتملة — **13/17**، المرحلة ج **2/4**

## التحقق القبلي

حُسمت هوية الهدفين قبل أي حذف، ولم يُعتمد تطابقٌ جزئي في الاسم:

| الاسم الدقيق | الصورة | الحالة | وسوم Compose | التخزين المرتبط |
|---|---|---|---|---|
| `/qdrant` | `qdrant/qdrant:latest` | `exited`، رمز 143 | غائبة | ربطان إلى `/home/anas/qdrant/storage` و`/home/anas/qdrant/snapshots` |
| `/vault` | `hashicorp/vault:latest` | `exited`، رمز 0 | غائبة | حجمان محليان مجهولا الاسم إلى `/vault/file` و`/vault/logs` |

في الوقت نفسه كان البديلان المقصودان عاملين ضمن Compose: `aizzak-qdrant-1` بالصورة المثبّتة `qdrant/qdrant:v1.13.4`، و`aizzak-vault-1` بالصورة المثبّتة `hashicorp/vault:1.18`.

## ما نُفّذ

نُفّذ أمر الخطة وحده:

```bash
docker rm -f qdrant vault
```

أعاد Docker الاسمين `qdrant` و`vault` وخرج بصفر. لم يُستخدم `-v`، ولم تُحذف صورة أو حجم أو مسار بيانات، ولم يُنفّذ `compose up` أو `restart`؛ إعادة التشغيل والمطابقة هما ج‑3 وحدها.

## البرهان بعد الحذف

- مرشّحا الاسم الدقيق `/qdrant` و`/vault` لا يعيدان أي حاوية.
- صورتا `qdrant/qdrant:latest` و`hashicorp/vault:latest` ما تزالان في مخزن الصور.
- حجما Vault المجهولان ما يزالان موجودين، ومسارا ربط Qdrant كلاهما دليلان باقيان.
- `aizzak-qdrant-1` و`aizzak-vault-1` بقيا عاملين، وبقيت خدمات Compose الإحدى عشرة طويلة التشغيل `Up`؛ سبع منها `healthy`.
- المنافذ الأصلية 5432 و6379 و6432 و9000 بقيت بلا منصت؛ منافذ Compose المزاحة بقيت عاملة.
- حاويات `alpha-infra-*` الأربع بقيت `Exited (0)` ولم تُمس، اتساقاً مع ن‑ب وخروجها الصريح من النطاق.
