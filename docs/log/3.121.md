# §3.121 — ب‑1: التشغيل الكامل مقابل الحزمة الحاويّة

**التاريخ:** 2026‑08‑05  
**الخطة:** [`containerised-test-harness-plan-v2.md`](../containerised-test-harness-plan-v2.md) — الخطوة ب‑1  
**النطاق:** رفع المكدّس الكامل وقياس الحزمة عليه؛ لا تشغيلٌ صريح لـ`live_stack_slo` ولا بوابة ب‑3

## 1. النتيجة

اكتملت ب‑1 وطابقت عقد الخطة حرفياً: **2522 ناجحاً · 0 فاشل · 10 متخطّيات**. كل اختبار يعتمد وجهةً محليةً بلغها ونجح: الخدمات الحاويّة مباشرةً، وOllama الأصلية داخل WSL عبر `ollama-bridge`. المتخطّيات العشر هي وحدها الحالات المقصودة التي تحتاج مفتاحاً خارجياً أو راية SLO صريحة.

التقدّم صار **9/17**، والمرحلة ب **1/3**. الخطوة التالية ب‑2 وحدها.

## 2. الإقلاع والبناء

نُفّذ الأمر بلا اختصار `--build`:

```bash
docker compose -f docker-compose.yml -f docker-compose.test.yml up -d --build
```

أعيد بناء `aizzak/app:dev` و`aizzak/embedding:dev` من الرأس الحالي، تطبيقاً للتحذير في `release-blockers-plan.md` ن‑4. حالة المكدّس بعد الإقلاع وبعد الاختبارات:

- **11 خدمةً طويلة عاملة**.
- سبعٌ `healthy`: `app`، `embedding`، `postgres`، `redis`، `minio`، `vault`، `nginx`.
- أربعٌ `Up` بلا فحص صحة معرّف: `ollama-bridge`، `outbox-relay`، `pgbouncer`، `qdrant`.
- أربع خدمات تهيئة خرجت بـ`0`: `migrate`، `vault-bootstrap`، `minio-bootstrap`، `nginx-certs`.

لم يُستعمل `down`؛ المكدّس وشبكة `aizzak_default` بقيا عاملين لأنّ ب‑2 تحتاج الشبكة نفسها.
