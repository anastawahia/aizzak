# §3.128 — ج‑4: التنظيف النهائي واكتمال المرحلة ج

> عودة إلى الفهرس: [`INDEX.md`](INDEX.md) · الخطة: [`../containerised-test-harness-plan-v2.md`](../containerised-test-harness-plan-v2.md) §ج‑4 · إثبات ما قبل الحذف: [§3.127](3.127.md)

## النتيجة

أُغلقت ج‑4، نقطة اللاعودة في خطة ترحيل عدّة الاختبار إلى الخدمات الحاويّة. أُزيلت الخوادم الأصلية المستهدفة وبياناتها المحلية، وبقيت الأدوات والخدمات المستثناة صراحةً. صار التقدم **15/17** واكتملت المرحلة ج **4/4**؛ التالية د‑1 وحدها.

## تثبيت الأهداف قبل الحذف

كانت الشجرة نظيفة عند البدء، وكانت ج‑3 ملتزمة في `7847c24`. قبل أي فعل هدّام ثُبّت الآتي:

- الحزم الأربع `postgresql-16` و`postgresql-client-16` و`pgbouncer` و`redis-server` كانت مثبتة.
- محاكاة `apt-get -s purge postgresql-16 pgbouncer redis-server` عرضت إزالة **الحزم الخادمية الثلاث وحدها**؛ لم تُدرج `postgresql-client-16`.
- `/var/lib/postgresql` و`/var/lib/redis` و`/var/lib/minio` أدلة حقيقية، و`/usr/local/bin/minio` ملف عادي؛ لا هدف منها رابط رمزي.
- `/usr/local/bin/ollama` ملف مستقل موجود، وخارج أمر الحذف.

## الإزالة الفعلية

نُفّذ بامتياز root داخل WSL، وهو المكافئ غير التفاعلي لـ`sudo` في نص الخطة:

```bash
apt purge -y postgresql-16 pgbouncer redis-server
rm -rf -- /var/lib/postgresql /var/lib/redis /var/lib/minio /usr/local/bin/minio
```

لم يُنفّذ `apt autoremove`، ولم تُحذف أي حزمة أو مسار زائد.

### سؤال `whiptail` الذي عطّل `apt`

رغم `-y`، فتح `postgresql-16.postrm purge` سؤالاً تفاعلياً عبر `debconf`/`whiptail`: هل تُحذف أدلة PostgreSQL عند purge؟ لم يعرض غلاف الأمر السؤال، فانتهت مهلته بعد 124 ثانية بينما بقيت سلسلة العمليات حيّة. لم يُعَد الأمر عمياناً؛ أظهر فحص شجرة العمليات السلسلة الدقيقة:

```text
apt purge -y …
└─ dpkg --purge --pending
   └─ debconf/frontend postgresql-16.postrm purge
      └─ postgresql-16.postrm purge
         └─ whiptail … Remove PostgreSQL directories when package is purged?
```

أُنهيت عملية `whiptail` وحدها بإشارة `TERM`، فانفك القفل وانتهت بقية السلسلة. أثبت `dpkg -l` بعدها أن `postgresql-16` و`redis-server` في حالة `un` وأن `pgbouncer` لم يعد له تطابق؛ أي إن إزالة الحزم اكتملت. بقيت أدلة البيانات، كما يسمح به سؤال postrm، ثم حذفها أمر ج‑4 الصريح التالي. لم يُحتج إلى إعادة `apt purge`.

وأثبت تدقيق ما بعد التعافي سلامة قاعدة الحزم: `dpkg --audit` بلا خرج، و`apt-get check` بامتياز root خرج 0 بعد بناء شجرة الاعتمادات بلا خطأ.

## حالة المضيف بعد الحذف

- الأهداف الأربعة غائبة: `/var/lib/postgresql` · `/var/lib/redis` · `/var/lib/minio` · `/usr/local/bin/minio`.
- `postgresql-client-16 16.14` بقي مثبتاً، و`/usr/bin/psql` يعمل (`psql 16.14`).
- `/usr/local/bin/ollama` بقي بلا مساس، وأمر `ollama --version` يعمل.
- `systemctl is-active postgresql pgbouncer redis-server` أعاد `inactive` للثلاثة.
- لا مستمع على المنافذ الأصلية 5432 أو 6379 أو 6432 أو 9000.

## حالة Compose بعد إزالة المضيف

لم تُعَد حاويات Compose ولم تُبنَ؛ المكدّس القائم نجا من حذف المضيف:

- 11 خدمةً طويلة عاملة.
- 7 خدمات `healthy`: `app` · `embedding` · `postgres` · `redis` · `minio` · `vault` · `nginx`.
- 4 خدمات `Up`: `ollama-bridge` · `outbox-relay` · `pgbouncer` · `qdrant`.
- 4 خدمات تهيئة `Exited (0)`: `migrate` · `vault-bootstrap` · `minio-bootstrap` · `nginx-certs`.

## انضباط ساعة WSL أثناء `pytest`

قبل البوابة عرض `timedatectl timesync-status` انحرافاً قدره `+2.909546s`. وبسبب عارض القفز الزمني المثبت في ج‑3، أُوقفت `systemd-timesyncd` مؤقتاً أثناء `pytest` فقط لمنع فشل زائف في اختباري Redis ذوي حدّي 2s/3s. بعد خروج الحزمة 0 أُعيدت الخدمة فوراً، وثبت أن حالتها `active`. لا تعطيل دائم ولا تعديل إعداد.
