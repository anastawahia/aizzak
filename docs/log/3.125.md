# §3.125 — ج‑1: الخدمات الأصلية المستهدفة متوقفة ومعطّلة بلا حذف

**التاريخ:** 2026‑08‑05  
**الخطة:** [`containerised-test-harness-plan-v2.md`](../containerised-test-harness-plan-v2.md)  
**الخطوة:** ج‑1 فقط — الإيقاف والتعطيل مع إبقاء البيانات والحزم  
**الحصيلة:** ✅ مكتملة — **12/17**، المرحلة ج **1/4**

## ما نُفّذ

- أثبت القياس القبلي أن PostgreSQL وحدها كانت وحدةً نظاميةً عاملة: `postgresql@16-main` و`postgresql` كلتاهما `active`؛ أما `pgbouncer` و`redis-server` و`minio` فكانت `inactive/disabled`.
- عُرّفت Redis الخارجة عن systemd قبل الإنهاء: `redis-server 0.0.0.0:6379`، ‏PID `1446`، المستخدم `anas`، داخل `user-1000.slice/session-1.scope`. أُعيد فحص اسم العملية مباشرةً قبل إرسال `TERM` إليها.
- عند فتح VS Code بعد ذلك عادت Redis بعملية جديدة PID `24895` في `init.scope`. تتبّع شجرة الآباء ومسار العمل ثم البحث في ملفات الإقلاع كشف المصدر: سطران متطابقان في `/home/anas/.bashrc` يشغّلان `redis-server --daemonize yes --bind 0.0.0.0 --protected-mode no` عند كل shell تفاعلية. حُذف السطران، ثم أُنهيت العملية الجديدة بعد إعادة مطابقة هويتها.
- شُغّلت shell تفاعلية جديدة بعد التصحيح؛ لم تعد Redis، وبقي `ss -ltnp` بلا 6379. وبذلك صار التعطيل ثابتاً عبر الجلسات لا إنهاءً مؤقتاً لعملية واحدة.
- نُفّذ `systemctl disable --now` للخدمات الخمس بامتياز root داخل WSL. هذا مكافئ للأمر الموثّق بـ`sudo`؛ استُخدم لأن `sudo` غير التفاعلي طلب كلمة مرور، لا لتغيير نطاق الخطوة.
- لم تُحذف حزمة أو بيانات، ولم تُمس Ollama، ولم تبدأ ج‑2.

## الحالة المثبتة

| الهدف | بعد ج‑1 |
|---|---|
| `postgresql` | `inactive / disabled` |
| `postgresql@16-main` | `inactive / enabled-runtime` — رابط يولّده `postgresql-generator` داخل `postgresql.service.wants` فقط |
| `pgbouncer` | `inactive / disabled` |
| `redis-server` | `inactive / disabled`؛ والعمليتان اليدويتان منتهيتان، ومصدر `.bashrc` محذوف ومختبر بجلسة جديدة |
| `minio` | `inactive / disabled` |
| 5432 · 6379 · 6432 · 9000 | لا مُنصت قبل البوابات ولا بعدها |

حالة `enabled-runtime` لا تعني بدءاً مستقلاً: `WantedBy=postgresql.service`، والوحدة الجامعة نفسها `disabled`، ولا يعرض `multi-user.target` أي تبعية PostgreSQL. أبقينا `/etc/postgresql/16/main/start.conf` على `auto` بلا تعديل، فتظل العودة سريعةً ولا يبدأ العنقود تلقائياً ما دامت الوحدة الجامعة معطلة.

الحزم `postgresql-16` و`pgbouncer` و`redis-server` ما تزال مثبّتة، والمسارات `/var/lib/postgresql` و`/var/lib/redis` و`/var/lib/minio` و`/usr/local/bin/minio` كلها باقية. وبذلك لم تُمس نقطة اللاعودة ج‑4.

مكدّس Compose بقي عاملاً على منافذه المزاحة، فغياب المنافذ الأصلية لم يقطعه.
