## 8. أوامر التنفيذ

> ✅ **نُفِّذت المرحلتان 1 و 3 بتاريخ 2026-08-15** بأمر المستخدم.
> ⛔ **المرحلة 2 (أحجام alpha) لم تُنفَّذ** — بأمر صريح: «بدون حذف بيانات alpha».
> تفاصيل ما جرى فعليًا في §10 أدناه.

> ⚠️ **لا تستخدم `docker system prune -a` هنا.**
> هي تحذف كل صورة لا تستخدمها حاوية **عاملة**، وهذا يشمل
> `minio/mc:RELEASE.2025-04-16T18-13-26Z` (116 MB) لأن حاويتها الوحيدة
> (`minio-bootstrap`) متوقفة بشكل طبيعي — فيُكسر البناء ويُعاد سحبها.
> الأوامر أدناه مُستهدَفة بدقّة.

**المرحلة 1 — آمنة تمامًا (≈ 9.25 GB):**

```bash
docker rm agitated_cray && docker rmi hello-world:latest && docker rmi aizzak/app:prefix hashicorp/vault:latest qdrant/qdrant:latest python:3-alpine alpine:3.20 alpine:latest && docker volume prune -f && docker builder prune -af
```

> `docker volume prune -f` بدون `--all` يحذف **الأحجام المجهولة غير المستخدمة فقط**،
> فلا يمسّ `aizzak_*` ولا `alpha-infra_*`. هذا هو السلوك المقصود هنا تحديدًا.

**المرحلة 2 — بعد قرارك بشأن بيانات alpha القديمة.**
🔴 alpha **ليس معطوبًا** (§4.3): مكدّسه متوقف وبياناته كاملة. الأمر الثاني أدناه
هو ما **يُعطبه** فعلًا. خذ النسخة الاحتياطية أولًا، ولا تشغّل الثاني إلا بقرار
واعٍ بأنك انتهيت من بيانات المشروع القديم:

```bash
docker run --rm -v alpha-infra_pg-data:/src -v "$PWD":/out alpine:3.20 tar czf /out/alpha-pg-data-backup.tar.gz -C /src .
```

```bash
docker volume rm alpha-infra_pg-data alpha-infra_minio-data alpha-infra_redis-data
```

**المرحلة 3 — اختيارية (تنظيف صفري):**

```bash

```
