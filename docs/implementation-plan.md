## 0.6 نطاق v1 وتصحيحات المطابقة (Scope Guardrails)

> نتيجة مراجعة الخطة ضد `Requirements-v1.md §6` — لتفادي بناء ما هو خارج النطاق.

**داخل v1 (`DAT‑01` · `FR‑20` · `FR‑120…134`):**
- **10 وحدات**: `workspace · access · credentials · conversations · memory · files · knowledge · media · integrations · usage` + schema `platform`.
- **5 وكلاء فقط**: RAG · Data Analysis · Image · Video · File Editing (`FR‑20`).
- **الأدوات الخارجية للوكلاء** تأتي **حصراً** عبر منفذ `integrations.ToolCatalog` (موصّلات مُفعّلة + **MCP بعيد HTTP/SSE فقط**) — `FR‑52/122`.

**خارج v1 (لا يُبنى الآن):**
- الوحدات المحجوزة `scheduling · sandbox · runs` (`§12.1`) — الأسماء محجوزة، لا schema.
- **MCP المحلي (stdio/عملية فرعية)** — يتبع `sandbox`/`ARC‑15`.
- الفوترة/الدفع المالي، والتجديد الاستباقي المجدوَل لـOAuth (`FR‑124` يعتمد التجديد الكسول فقط).

**تصحيحات على النسخة v1.0 من هذه الخطة (⚠️ مهمّ):**
- **Gmail ليس أداة مثبّتة** بل **موصّل في وحدة `integrations`** (OAuth) يُستهلَك عبر `ToolCatalog` — نُقل من المرحلة 4 إلى المرحلة 3.
- أدوات `alpha` العامة **weather · currency · news · sports** **خارج نطاق v1** (كانت تخدم وكيل دردشة عامّاً لا وجود له هنا) — تُؤجَّل كموصّلات/MCP مستقبلية.
- `web_search` و`calculator` يُعاملان **كأمثلة مرجعية اختيارية** لعقد `BaseTool`، لا كمتطلّب.
