دليل الإصدار والتثبيت

بناء الصور ← الوسم ← الحزمة ← التثبيت على الخادم الجديد. استبدل 2026.10.3 برقم إصدارك (الصيغة YYYY.M.N بلا حرف v).

1تأكد أن الكود جاهز

على جهازك — داخل /home/AIZZAK
git switch master && git pull
git status            # يجب أن تكون الشجرة نظيفة
.venv/bin/ruff format --check . && .venv/bin/ruff check . && .venv/bin/mypy src && .venv/bin/lint-imports
الإصدار يُبنى فقط من commit موجود على origin/master وCI أخضر له.

2الوسم = بناء الصور ورفعها (تلقائي)

على جهازك
git tag v2026.10.3
git push origin v2026.10.3

الوسم يشغّل GitHub Actions (release.yml): يبني الصور الثلاث (app وembedding وembedding-cuda) ويرفعها إلى anastawahia/aizzak على Docker Hub. تابعه:

gh run watch
ظهور "Bypassed rule violations" عند دفع الوسم طبيعي: قاعدة GitHub تقيّد إنشاء الوسوم وأنت تتجاوزها بصلاحية المالك.
إن فشل بعد أن رُفعت صورة، الرقم يُهجر: أصدر الرقم التالي (2026.10.4). لا تعيد نفس الرقم.
ارفع وسماً واحداً فقط في كل مرة، فكل وسم يطلق بناءً كاملاً.
البناء اليدوي من جهازك للطوارئ فقط (بطيء جداً): deploy/release/build-push.sh 2026.10.3

3نزّل ملف البصمات

على جهازك — بعد نجاح الخطوة 2
RUN=$(gh run list --workflow=release.yml --branch v2026.10.3 --limit 1 --json databaseId -q '.[0].databaseId')
gh run download "$RUN" -n release-digests -D /tmp/rel
cat /tmp/rel/release-digests.txt     # يجب أن ترى 3 أسطر
الخيار --branch v2026.10.3 ضروري: بدونه يؤخذ أحدث تشغيل مهما كان وسمه، وقد يكون ملغى أو فاشلاً بلا أثر ("no valid artifacts found").

4اصنع الحزمة

على جهازك — داخل /home/AIZZAK
deploy/release/bundle.sh --digests /tmp/rel/release-digests.txt --out /tmp/rel 2026.10.3

يطبع مسار الحزمة aizzak-2026.10.3.tar.gz ومعها قيمة sha256. احفظ هذه القيمة.

5ارفع الحزمة إلى الخادم

على جهازك
scp /tmp/rel/aizzak-2026.10.3.tar.gz USER@SERVER_IP:/tmp/

6جهّز الخادم (مرة واحدة فقط)

على الخادم

يلزم: Docker ≥ 26 وCompose ≥ 2.20، وPython 3.10+ مع PyYAML، وعلى الكرت: تعريف NVIDIA وContainer Toolkit ≥ 1.17.8.

sudo apt-get install -y python3-yaml
sudo docker login docker.io -u anastawahia     # مفتاح قراءة فقط خاص بهذا الخادم

7تحقق وفكّ الحزمة

على الخادم
sha256sum /tmp/aizzak-2026.10.3.tar.gz     # قارنها بقيمة الخطوة 4
sudo tar -xzf /tmp/aizzak-2026.10.3.tar.gz -C /opt
cd /opt/aizzak-2026.10.3
إن اختلفت القيمة لا تكمل.

8ثبّت

على الخادم — داخل مجلد الحزمة
sudo ./install.sh --domain example.com --firebase-project aizzak-agent

خيارات مفيدة: --cpu (بلا كرت)، --size small|medium|large، --no-monitoring. النجاح ينتهي بـ READY ورمز خروج 0. إن توقف في المنتصف أعد نفس الأمر وسيكمل.

لا تشغّل docker compose up بيدك قبل أن ينتهي التثبيت.

9بعد التثبيت

على الخادم
chmod 600 .env
curl -fsS https://example.com/health
sudo docker compose ps
  • انسخ حجم vault-init إلى مكان آمن خارج الخادم.
  • سجّل تاريخ انتهاء VAULT_SECRET_ID (ينتهي بعد 720 ساعة، ويطبعه التقرير).
  • الشهادة والمنافذ: انظر docs/deploy-server.md §4–§5.

إن فشل شيء

  • رمز الخروج يدل على السبب: جدوله في docs/deploy-server.md §3.5 (مثلاً 13 = تسجيل دخول Docker ناقص، 60 = خطوة إقلاع فشلت).
  • سجلات خدمة: sudo docker compose logs SERVICE
  • الترقية لإصدار جديد على خادم مثبّت ليست من عمل install.sh (مخطط لها في upgrade.sh، الخطوة 5.3).
