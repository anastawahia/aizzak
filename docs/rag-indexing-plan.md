## 3. التصميم

### 3.1 مسار PDF الثلاثي (‏`P-06` `P-07` `P-10`)

```
bytes ──► ملفّ مؤقّت ──┬─► ١. Camelot stream ──► جداول + table_locations
                       │                         (عتبة accuracy 60 · أعمدة ≥ 2)
                       ├─► ٢. مستخرج التخطيط ──► بلوكات تتجنّب table_locations
                       │      (fitz · sort=True)   بعتبة تداخل 0.5
                       └─► ٣. مستخرج الصور ────► OCR على ما تبقّى
                              └─ finally: حذف الملفّ المؤقّت
```

**لماذا ملفّ مؤقّت:** Camelot يقرأ **من مسار** لا من بايتات، و AIZZAK كائنيّ. العامل يكتب الملفّ ويحذفه في `finally`. تفصيل تنفيذيّ لا خيار.

**ما يُنقَل من خوارزمية الجداول** (‏`pdf_table_extractor.py`، ٩٤٤ سطرًا):

| القطعة | القيمة المنقولة | التعليل المنقول |
|---|---|---|
| عتبة الدقّة | `STREAM_MIN_ACCURACY = 60` | مقياس `accuracy` من Camelot نفسه (ح‑١٥) — لا يُخترَع بديل |
| حدّ الأعمدة | `TABLE_MIN_COLUMNS = 2` | يرفض نصًّا صُنِّف خطأً جدولًا — أهمّ حارس ضجيج في البند |
| دمج الجداول عبر الصفحات | `detect_continued_tables` + `merge_continued_tables` بتشابه الأعمدة | جدول يمتدّ على ثلاث صفحات جدولٌ واحد لا ثلاثة |
| التسمية التوضيحية | `_extract_table_caption` | تصير `table_name` في الحمولة — مفتاح استشهاد قائم |
| تجنّب المناطق | `PDF_TABLE_OVERLAP_THRESHOLD = 0.5` | بدونه يُفهرَس كلّ جدول **مرّتين**: منظَّمًا ونصًّا مشوَّشًا |

**ما لا يُنقَل:** نكهة `lattice`. سببه ترخيصيّ لا تقنيّ: `lattice` يجرّ ghostscript (‏**AGPL**) و`pyproject` يعلن المشروع `Proprietary`. **الأثر المُعلَن:** الجداول المؤطَّرة تُكتشف أضعف من `stream` — وهي شائعة في المستندات العربية الرسميّة. ثمنٌ معروف ومقبول بالقرار س-04.

**البلوكات (‏`P-10`):** `MIN_BLOCK_CHARS = 25` ينتقل من الصفحة إلى **البلوك**؛ `page.get_text("blocks", sort=True)` يحفظ ترتيب القراءة RTL كما هو اليوم؛ كلّ بلوك يحمل `page_number` و`position_in_doc`. `ParsedChunk.order` للـ PDF يصير **رتبة بلوك** لا رقم صفحة ⇒ لا تُغلَق الخطوة ٢ قبل الخطوة ١٠ (`P-17`).

### 3.2 قطع الأب (‏`P-14`)

```sql
CREATE TABLE knowledge.parent_chunks (
  id           uuid PRIMARY KEY,
  document_id  uuid NOT NULL REFERENCES knowledge.documents(id) ON DELETE CASCADE,
  workspace_id uuid NOT NULL,
  seq          integer NOT NULL,
  text         text    NOT NULL,
  created_at   timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uq_parent_seq UNIQUE (document_id, seq)
);
-- RLS: workspace_id = NULLIF(current_setting('app.workspace_id', true), '')::uuid
-- + عمود على chunks:  parent_id uuid NULL REFERENCES knowledge.parent_chunks(id)
```

**المكسب البنيويّ:** `SourceSegment` هو الأب طبيعيًّا — `chunk_segments` يبني النوافذ **داخل كلّ مقطع على حدة** ولا تعبر نافذةٌ حدَّ مقطع أبدًا. فلا مرحلة تحليل إضافية ولا `parent_chunks.json`.

**ثلاثة قيود لا تُخرَق:**
1. `parent_id` عمودٌ على `chunks` في SQL (أعلاه) — لا حقلًا في حمولة Qdrant. توسيع الأب عند الاسترجاع استعلامُ **مستودع** (‏`chunk_id → chunks.parent_id → parent_chunks`، خطّة الاسترجاع §3.7 `P-34`) لا قراءة حمولة. حمولة Qdrant **لا تحمل لا نصّ الأب ولا معرّفه** — تعليل alpha الصريح باقٍ ويحكم الاثنين معًا: حقن نصّ الأب في كلّ نقطة يضخّم المخزن N مرّة؛ ونفس المنطق يُسقط حتّى المعرّف وحده معه، فتكراره N مرّة بلا فائدة ما دام `chunk_id` (موجودٌ في الحمولة أصلًا) كافيًا للمستودع ليصل إلى `chunks.parent_id` بعمود SQL واحد.
2. الجدول جديد ولا يُخلَط بـ`chunks` (ح‑٨): بقاء «كلّ صفّ في `chunks` = نقطة في Qdrant» شرطٌ لسلامة `chunk_count` و`UNIQUE(document_id, seq)`.
3. `ON DELETE CASCADE` على `document_id` حتّى يبقى الحذف المتسلسل القائم صحيحًا بلا سطر جديد.

### 3.3 الجداول: التفجير والأب والسقف (‏`P-13` + س-07)

```
جدول بـ R صفًّا
├─ R ≤ 20        ──► كلّ صفّ عقدة + نصّ الجدول الكامل أبًا   (TABLE_PARENT_MAX_ROWS)
├─ 20 < R ≤ 2000 ──► كلّ صفّ عقدة + رأس الجدول أبًا
└─ R > 2000      ──► أوّل 2000 صفّ عقدًا + الباقي نافذة كلمات + علم truncated معلَن
```

**سَلسَلة الصفّ** (‏`row_to_sentence`): `"العمود: القيمة; العمود: القيمة"` — **محايدة لغويًّا** (لا كلمات ربط إنجليزية)، مع إسقاط أعمدة الضجيج `no. / no / row / # / index / id` والقيم الفارغة.

**التعليل المنقول:** المكسب ليس تجميليًّا — «كم راتب أحمد؟» تجد **صفّ أحمد** كاملًا بدل شذرة من ثلاثة صفوف نصفها مبتور. وهذا **أعلى مكسب مفرد في الاسترجاع** في الخطّة كلّها.

**السقف تعليله عدديّ:** ورقة بـ ٥٠٠٠ صفّ بلا سقف = ٥٠٠٠ استدعاء تضمين + ٥٠٠٠ نقطة Qdrant + ٥٠٠٠ صفّ في `chunks` **لملفّ واحد**. البتر يُعلَن كنمط `truncated` القائم في التلخيص — صدق البتر مكسب AIZZAK لا يُكسَر.

### 3.4 التقسيم الدلالي بلا كسر نقاء الدومين (‏`P-20`)

القرار س-06 = ج يُدخِل البند، وسؤاله التصميميّ الوحيد أن الخوارزمية تحتاج **المُضمِّن** والدومين نقيّ. الحلّ **فصل الحساب عن النداء**:

```
application/indexing.py  ──► يقسّم المقطع إلى جمل
                         ──► ينادي EmbeddingProvider على الجمل     ← I/O هنا، حيث هو أصلًا
                         ──► يمرّر المتّجهات إلى الدومين
domain/chunking.py       ──► semantic_boundaries(vectors, *, buffer=1,
                                                 breakpoint_percentile=95) -> list[int]
                              دالّة نقيّة: مسافة جيب التمام بين مجموعات جمل متعاقبة،
                              وقطعٌ عند المئين ٩٥ من التوزيع. لا شبكة ولا مزوّد.
```

**النتيجة:** الخوارزمية والمعايرة (‏`buffer=1` · `breakpoint_percentile=95`) تُنقَلان كما هما، والدومين يبقى نقيًّا، والاختبار الوحدويّ يعمل بلا شبكة.

**أربعة قيود:**
1. **نافذة الكلمات تبقى سقفًا صلبًا** بعد الحدود الدلالية — جزءٌ دلاليّ أطول من الحدّ يُقطَّع بالنافذة كما اليوم.
2. **المقاطع الجدولية تتخطّى التقسيم الدلالي** كلّيًّا — الصفّ ذرّة أصلًا (§3.3).
3. **الكلفة التشغيلية دائمة ومُعلَنة:** تمريرة تضمين إضافية على جمل كلّ مستند عند كلّ فهرسة — و**تمريرة واحدة مُجمَّعة فعلًا** (‏أُضيف التوضيح 2026‑08‑20 مع إغلاق §4 من المراجعة): جمل القطع تُحزَم في نداءات بسقف `_EMBED_BATCH` نفسه الذي تحكم به تمريرة العقد الإلزاميّة، لا نداءً متتابعًا لكلّ قطعة. القطعة لا تُشطَر بين حزمتين (‏كشف الحدود يحتاج متّجهاتها معًا)، والقطعة التي تتجاوز السقف وحدها تُخدَم بعدّة نداءات بحجم السقف تتلاحق متّجهاتها.
4. **فشل التمريرة غير قاتل** (‏أُضيف 2026‑08‑20 مع إغلاق §3 من المراجعة): التقسيم الدلالي **تحسينٌ اختياريّ** — كلّ مقطع يمرّ به له تمثيل صحيح كامل بدونه أصلًا. فشل المزوّد على نداء الجمل ⇒ **سقوط إلى المقطع غير المقسوم** مع تحذير مُسجَّل، لا إسقاط المستند كلّه؛ وإلّا لنقضت هذه الخطوة ضمانة الخطوة ١٢ (`P-19`) بعد خطوة واحدة. ولا نجاح كاذب: تمريرة العقد **الإلزاميّة** تنادي المزوّد نفسه، فمزوّد ساقط فعلًا يُسقِط المستند من هناك. ومع التجميع (‏قيد ٣) يضيّق فشل الحزمة إلى **قطعة واحدة لكلّ نداء** على غرار `P-19` قبل التنازل، فلا يتنازل إلّا مَن يفشل وحده.

**تقسيم الجمل عربيًّا:** الفواصل `.` `؟` `!` `؛` `\n\n` والنقطة العربية — لا `nltk` ولا تبعية جديدة.

### 3.5 حدّ الرموز الحقيقي (‏`P-16` + س-11)

`Settings.embedding_max_input_tokens` (افتراض **512**، يُتحقَّق منه مقابل النموذج المنشور عند التنفيذ) يُمرَّر **كوسيط** إلى `domain/chunking.py`. صيغة alpha تُنقَل كما هي:

```
max_words = max(int((embedding_max_input_tokens / 1.3) * 0.9), 32)   # تداخل ١٠٪ عند الانقسام
```

**التعليل المنقول:** البتر عند مزوّد HTTP **صامت** — القطعة تُضمَّن ناقصة ولا أحد يعلم، وأوّل ضحاياه ذيول الجداول الطويلة. والعربية أكثر رموزًا لكلّ حرف من الإنجليزية، فتقدير `len//4` (ح‑٧) يخطئ **في اتّجاه الخطر**؛ لذلك المعامل `1.3` مُبقًى ولا يُخفَّض.

### 3.6 بصمة المحتوى ومصيدة التخطّي (‏`P-03` + س-14)

`content_hash = sha256(bytes)` عمودًا على `documents` — **لا `mtime`**: النموذج كائنيّ لا ملفّيّ.

**⚠️ مصيدة صريحة، وحلّها جزء من الخطوة ١٥:** لو كان التخطّي على البصمة وحدها، لصارت **ترقية أيّ محلّل بلا أثر**: البايتات نفسها ⇒ البصمة نفسها ⇒ تخطٍّ ⇒ قطعٌ قديمة الشكل تبقى إلى الأبد. لذلك يُقارَن **الزوج**:

```
skip  ⇔  content_hash غير متغيّر  AND  pipeline_version غير متغيّر
```

`pipeline_version` ثابتٌ واحد في `domain/` يُرفَع يدويًّا في كلّ خطوة تغيّر شكل المخرَج (‏٢ · ٣ · ٤ · ٥ · ٧ · ٩ · ١٠ · ١١ · ١٣). ورفعه هو ما يجعل §5 قابلة للتنفيذ.

**إبطال الملخّص:** تغيّر `content_hash` يحذف صفوف `summaries` للمستند — يغلق عطبًا حقيقيًّا: ملخّص يصف نسخة قديمة من الملفّ.

### 3.7 حارس المدخلات وسلوك الفشل (‏`P-01` `P-02` + س-13)

| الإعداد | القيمة | التعليل |
|---|---|---|
| `parser_max_uncompressed_mb` | **512** | سقف مجموع الأحجام المفكوكة لأرشيف Office |
| `parser_max_compression_ratio` | **100** | ملفّ Office مشروع بين ‎3:1‎ و‎10:1‎؛ ‎100:1‎ حدّ قنبلة لا حدّ استعمال |
| `parser_timeout_seconds` | **300** | يسع PDF ثقيلًا مع OCR تحت سقوف §3.8 |

القيم في `Settings` — **تُختار ولا تُنسَخ**، لأن alpha يقرؤها من البيئة ولا يوثّقها كقرار.

**سلوك الفشل (س-13 = أ):** الحارس أو المهلة ⇒ المستند `status='failed'` و`error` برسالة صريحة. **لا «تخطَّ وسجِّل»**: سلوك alpha يناسب مسح مجلَّد، وفي نموذج كائنيّ بمستند واحد لكلّ طلب يعني **نجاحًا كاذبًا بصفر قطع** — مستند يبدو مفهرَسًا وهو فارغ.

**المهلة تقنيًّا:** `asyncio.wait_for` حول `asyncio.to_thread` في العامل — **لا `SIGALRM`** (لا يعمل خارج الخيط الرئيسيّ، وموثَّق في `extractor.py` أنه لم يُنقَل).

### 3.8 OCR الصور المضمَّنة (‏`P-09` `P-11` + س-10)

| الإعداد | القيمة | التعليل |
|---|---|---|
| `ocr_min_image_px` | **200×200** | الأيقونات والشعارات أكثر الصور عددًا وأقلّها محتوًى |
| `ocr_max_images_per_document` | **40** | حارس الطابور: PDF من ١٠٠ صفحة قد يحمل مئات الصور |
| `ocr_max_images_per_page` | **8** | يمنع صفحة واحدة من ابتلاع سقف المستند |

**ما يُنقَل:** استخراج `word/media/*` و`xl/media/*` وصور PDF · **الدمج على مستوى الصفحة** · إزالة التكرار بـ`sha1` عبر الملفّ (‏`sha1_digest` موجود أصلًا) · الدمج تحت **نفس** `source_path` لا كملفّات يتيمة · `clean_ocr_text` و`create_page_summary` (ح‑٤) · `is_meaningful_text` · النصّ البديل `[Diagram/Chart WxHpx]` للصور بلا نصّ.

**تجاوز السقف يُعلَن ولا يُسقِط المستند** — نمط `truncated` نفسه؛ سقف OCR ليس عطبًا بل قرار كلفة.

### 3.9 مفاتيح الحمولة (‏`P-18`)

```python
_CITATION_KEYS = ("file_name", "page_number", "section", "sheet_name",
                  "section_type", "table_name")
```

كلفة الشيفرة شبه صفرية، **وتفتح المرحلة ٥ كلّها**: بلا `file_name` و`page_number` و`section` لا يستطيع النموذج الاستشهاد ولو أُمِر بذلك (تفصيله في خطّة الاسترجاع).

⚠️ **مفتاح جديد = إعادة فهرسة** (ح‑١٣): النقطة القديمة لا تحمل المفتاح، وأيّ ترشيح به لا يطابقها **بصمت**. §5 إلزاميّة بعد هذه الخطوة.

## 5. الترحيل التشغيليّ — إعادة بناء نظيف

**القرار س-03 = أ.** لا أداة إعادة فهرسة جديدة ولا مسار ترحيل بيانات؛ الإجراء يدويّ لأن البيئة فارغة اليوم (مُسح كلّ المحتوى التطويريّ 2026‑08‑16).

**متى:** بعد كلّ خطوة تغيّر شكل المخزَّن — أي بعد **٢ · ٣ · ٤ · ٥ · ٧ · ٩ · ١٠ · ١١ · ١٣**. والأرخص تجميعها: نفّذ أ و ب كاملتين ثمّ أعد البناء **مرّة واحدة**.

**الإجراء:**
1. حذف تجميعة `kn-<workspace_id>` من Qdrant.
2. `DELETE` من `knowledge.chunks` و`knowledge.parent_chunks` و`knowledge.summaries` لمساحة العمل.
3. رفع `pipeline_version` (§3.6) — يمنع تخطّي البصمة من إبطال إعادة البناء.
4. إعادة فهرسة كلّ مستند من MinIO عبر المسار القائم.

> ⚠️ **ح‑١٣ يجعل هذا إلزاميًّا لا احتياطيًّا.** نقطةٌ تنقصها `file_name` أو `parent_id` أو `section` **لا تطابق أيّ استعلام مُفلتَر بها، بلا خطأ ولا سجلّ**. نشرٌ جزئيّ لا يُنتج عطبًا مرئيًّا بل **نتائج ناقصة لا يلاحظها أحد**.

> ⚠️ **قبل أوّل بيانات حقيقية.** لحظة وجود محتوى مستخدم فعليّ تصير هذه الفقرة عاجزة، ويصير بندٌ جديد (أمر إعادة فهرسة فوق `knowledge.reindex_jobs` القائم) شرطًا لأيّ خطوة من المجموعة ب. **هذا هو الحدّ الزمنيّ الوحيد في الخطّة.**

## 7. خارج النطاق — يُسجَّل ولا يُنفَّذ

- **`P-12` كلّه** (‏`.xls` · `.doc` · `.tif` · `.tiff` · `.bmp` · `.gif`) — القرار س-12 = د. الصور الأربع كانت **مجّانية** (‏Pillow يقرؤها اليوم) والقرار أسقطها مع الباقي.
- **نكهة Camelot `lattice`** وghostscript — قرار ترخيص (س-04)، لا يُعاد فتحه إلا بتغيّر ترخيص المشروع.
- **التقطيع الهرمي** و**نافذة الجمل** — استثناءان مُقفلان.
- **`rank_bm25`** — إعادة بناء O(الكوربوس) لكلّ إضافة؛ IDF على جانب Qdrant يجعل الفهرسة تزايدية حقًّا.
- **حقن الميتاداتا في نصّ العقدة** — يلوّث التضمين و IDF معًا؛ تسميات المصدر تُضاف **عند العرض** (خطّة الاسترجاع) لا عند الفهرسة.
- **أمر إعادة فهرسة تشغيليّ** فوق `knowledge.reindex_jobs` — أسقطه القرار س-03 = أ. ⚠️ يعود شرطًا لازمًا لحظة وجود بيانات حقيقية (§5).
- **حمل إحداثيات البلوك تحت اسم `bbox`** — الخطوة ٢ تُصدرها باسم `block_bbox` عمدًا: `pdf_tables.py` يُصدر `bbox` في فضاء camelot (أصل أسفل-يسار) بينما البلوك في فضاء fitz (أصل أعلى-يسار)، والخطوة ٣ تضع النوعين في مستند واحد. توحيدهما — إن لزم — قرار عرضٍ لاحق.
- ~~ترتيب جدولٍ وبلوكٍ داخل الصفحة الواحدة~~ **حُسم في الخطوة ١٠:** مفتاح `_order_key` يحسم التعادل بإشارة `position_in_doc` الحقيقية (البلوك يحملها، الجدول لا) بدل ترتيب المرحلتين وحده — والبلوك الآن يسبق الجدول المتعادل معه رتبةً، عكس سلوك ما قبل الخطوة ١٠. ⚠️ **محدودية موثَّقة داخل `chunking.py` نفسها:** `position_in_doc` ليس مقياسًا واحدًا عبر كلّ منتِج PDF — `pdf_text.py`/`docx.py` عدّاد وثيقة-كامل تصاعديّ، بينما `image_ocr.py::_pdf_groups` يضع فيه `page_index` (رقم الصفحة) فقط؛ فمجموعة OCR لصفحة تسبق جدول تلك الصفحة دائمًا (تحمل الإشارة والجدول لا)، وقد تسبق بلوكات تلك الصفحة أيضًا في مستند طويل — عكس مقصد `_PAGE_OCR_ORDER_INDEX=999` القديم (الصور آخرًا). إصلاحه يستلزم تعديل `image_ocr.py` — خارج نطاق الخطوة ١٠ (‏`domain/chunking.py` فقط).
- **`position_in_doc` ليس على مقياس واحد عبر كلّ منتِج** — `pdf_text.py` و`docx.py` يختمانه عدّاد وثيقة-كامل تصاعديّ، بينما `image_ocr.py::_pdf_groups` يضع فيه `page_index` (رقم صفحة فقط). تحت مفتاح ترتيب الخطوة ١٠ بقاعدة NULLS-LAST، هذا يجعل مجموعة صور-OCR لصفحة PDF **تسبق** جدول تلك الصفحة نفسها، وغالبًا تسبق حتّى بلوكات نصّ تلك الصفحة — عكس مقصد `_PAGE_OCR_ORDER_INDEX = 999` (الصور آخرًا). الإصلاح مكانه `image_ocr.py` (ملفّ من المجموعة أ، مُقفَل ✅ بالفعل) لا `domain/chunking.py`. السلوك الحاليّ مثبَّت باختبار `test_ordering_key_a_pdf_page_images_group_outranks_that_pages_table`.
- **قاعدة «صفحة الجدول» تُسقط بقايا الصفحة** — منقولة من alpha (‏`MIN_BLOCK_CHARS * 2`) وتعمل **فقط** على صفحة تُجُنِّبت فيها مناطق جداول. على مستند تكون فيه بقايا الخلايا نصًّا مقصودًا، هذه هي المعايرة التي تُراجَع أوّلًا.
- **مفردات العناوين الإنجليزية وحدها** (‏`_HEADING_KEYWORDS`) — القرار س-09 = أ يجعل نمط Word هو الإشارة الأولى، وهي محايدة لغويًّا، ويُبقي الكلمات المفتاحية سقوطًا كما في alpha. **الأثر المعلَن:** مستند عربيّ كُتب بلا أنماط لا يُكشَف فيه أيّ عنوان (‏`_is_title` يردّ أيضًا كلّ سطر ينتهي بنقطة). المفردات العربية كانت الخيار (ب) ولم يُؤخَذ — وهي أوّل ما يُراجَع إن ظهر محتوى غير مُنسَّق.
- **صدارة `[Page Context: …]` إنجليزية داخل نصّ العقدة** — `create_page_summary` منقول بحكم ح‑٤ و§3.8، لكنه يصطدم بقاعدة §7 نفسها («حقن الميتاداتا في نصّ العقدة»). التخفيف المُطبَّق: الصدارة تُضاف **فقط** لمجموعة فيها صورة بلا نصّ، فالصفحة النظيفة لا تُحشى بها أبدًا، والملخّص مُكرَّر في `page_summary` بالحمولة ليأخذه العرض بدل النصّ. **وهي أوّل ما يُنقَل إلى الحمولة وحدها إن ظهر أثره في الاسترجاع.**
- **صور الأرشيف بلا موضع في المستند** — ‏`word/media/` و`xl/media/` لا يقولان أين تقع الصورة (الموضع في علاقة الرسم داخل `document.xml`)، فمجموعتها واحدة برتبة ثابتة تلي كلّ ما له موضع. قراءة العلاقات لإعطائها موضعًا حقيقيًّا خارج النطاق، وهي ما يُفتَح إن لزم تشابك الصور مع الفقرات.
- **`parse_image` بلا فلتر حجم وبلا نصّ بديل** — الصورة المرفوعة وحدها **هي** المستند: رفض ‎150×150‎ أو الإجابة عنها بـ`[Diagram/Chart 150x150px]` نصًّا كاملًا ضجيج لا محتوى. الفلتر والنصّ البديل للصور المضمَّنة التي لم يخترها المستخدم.
- **لغة OCR ثابتة في الوحدة** (‏`ara+eng`) ولم تُرفَع إلى `Settings` — قرار موثَّق (خطر #2 في `parsers.md`) لا معايرة نشر؛ رفعه بندٌ مستقلّ إن ظهرت نشرة بلغة ثالثة.
- **جداول DOCX تخرج بشكل `{headers, rows}` نفسه** الذي يخرج به Excel وPDF — عمدًا: تفجير الصفوف في الخطوة ٧ (`P-13`) يعمل فوق هذا الشكل، فلا يحتاج DOCX عملًا خاصًّا هناك.
- ~~`refine` (‏`P-45`) اختياريّ: يُنفَّذ آخرًا أو يُترك بلا أثر على بقيّة الخطّة~~ **نُفِّذت في الخطوة ٢١:** ``SummarizeDocument.refine`` بديلٌ حقيقيّ لا يُعيد تشكيل مسار الطيّ والاختزال — قراءة متتابعة بمُصنَع واحد حيّ طوال البناء (`_REFINE_SYSTEM`) بلا خطوة اختزال منفصلة، مقابل كلفة تسلسليّة (لا توازي بين الدفعات) هي ثمن الاستمراريّة عبر الوثيقة كلّها.
