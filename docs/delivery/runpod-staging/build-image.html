cd /home/AIZZAK

fb5765b fix(runpod): boot Vault and log the app into it

النتيجة المتوقعة: لا شيء، أو سطر واحد فقط هو ?? docs/delivery/runpod-staging/ (هذا الملف نفسه). أي تعديل آخر يعني أن الصورة لن تطابق ما راجعناه، فأخبرني به قبل البناء.

ابنِ الصورة

من داخل /home/AIZZAK نفّذ أمر البناء. انتبه للنقطة في آخر الأمر، فهي تعني «المجلد الحالي».

docker build --platform linux/amd64 -f deploy/runpod/Dockerfile -t aizzak-runpod:staging-1 .
  • يحمّل Ubuntu وPostgres وOllama ومكتبات Python ونموذج التضمين، لذلك يأخذ وقتاً حسب سرعة الإنترنت.
  • ستظهر مراحل مرقّمة مثل [runtime 5/14]. هذا طبيعي.
  • لا تغلق الطرفية حتى ينتهي. إن انقطع البناء فأعد الأمر نفسه، فهو يكمل مما انتهى إليه.
النتيجة المتوقعة: ينتهي دون كلمة ERROR، وآخر الأسطر يذكر اسم الصورة:
=> => naming to docker.io/library/aizzak-runpod:staging-1
إن فشل البناءانسخ آخر 30 سطراً من الطرفية وأرسلها لي. أغلب الأعطال هنا سببها انقطاع الإنترنت، وإعادة الأمر تكفي.
4

افحص الصورة (خمسة فحوص سريعة)

كل أمر هنا يشغّل الصورة لحظة لينفّذ فحصاً واحداً ثم يُغلقها. لا يبدأ أي خادم.

أ. حجم الصورة

docker image ls aizzak-runpod
النتيجة المتوقعة: سطر واحد بالوسم staging-1. سجّل الحجم، فهو ما سترفعه لاحقاً.

ب. لا أسرار ولا بيانات مستخدمين داخل الصورة

docker run --rm aizzak-runpod:staging-1 sh -c 'find /app \( -name accounts.json -o -name tokens.json -o -name include-workspaces.txt -o -name ".env*" -o -path "*/deploy/load/seeds" -o -path "*/deploy/load/results" \) -print; echo CHECK-DONE'
النتيجة المتوقعة: سطر واحد فقط هو CHECK-DONE. أي اسم ملف يظهر قبله يعني أن الصورة تحمل سراً، فلا ترفعها وأخبرني.

ج. الخط العربي لملفات PDF

docker run --rm aizzak-runpod:staging-1 sh -c 'ls /usr/share/fonts/truetype/noto | grep -c Arabic'
النتيجة المتوقعة: رقم أكبر من صفر.

د. مكتبة إنشاء PDF

docker run --rm aizzak-runpod:staging-1 /opt/venv/bin/python -c "import weasyprint; print('weasyprint', weasyprint.__version__)"
النتيجة المتوقعة: سطر مثل weasyprint 6x.x دون أي خطأ.

هـ. سكربت دخول Vault الجديد

docker run --rm aizzak-runpod:staging-1 ls -l /usr/local/bin/aizzak-with-vault
النتيجة المتوقعة: السطر يبدأ بـ -rwxr-xr-x (أي أنه قابل للتشغيل).
5

جهّز ملف إعدادات للتجربة

التجربة تحتاج 14 قيمة. هذه الأوامر تولّد كلمات سر عشوائية في ملف خارج المشروع. هذه القيم للتجربة المحلية فقط، وسنولّد قيماً جديدة للـ Pod.

mkdir -p ~/aizzak-runpod-test
{
  for v in POSTGRES_SUPERUSER_PASSWORD AIZZAK_OWNER_PASSWORD APP_RW_PASSWORD \
           OUTBOX_RELAY_PASSWORD RETENTION_SWEEPER_PASSWORD METRICS_READER_PASSWORD \
           TRANSIT_ROTATOR_PASSWORD WORKSPACE_PURGER_PASSWORD BACKUP_OPERATOR_PASSWORD \
           MINIO_ROOT_PASSWORD; do
    echo "$v=$(openssl rand -hex 24)"
  done
  echo "MINIO_ROOT_USER=aizzak-admin"
  echo "FIREBASE_PROJECT_ID=aizzak-agent"
  echo "APP_ENV=staging"
  echo "WEB_CONCURRENCY=1"
} > ~/aizzak-runpod-test/test.env
chmod 600 ~/aizzak-runpod-test/test.env
grep -c = ~/aizzak-runpod-test/test.env
النتيجة المتوقعة: 14.
قيمتان تستحقان الانتباه
  • FIREBASE_PROJECT_ID=aizzak-agent استنتجته من إعدادات CORS. إن كان اسم مشروعك في Firebase مختلفاً فعدّله في الملف. للتجربة المحلية تكفي أي قيمة غير فارغة.
  • WEB_CONCURRENCY=1 يقلّل استهلاك الذاكرة على جهازك، لأن المكدّس الحالي يعمل في الوقت نفسه. على RunPod سنستخدم القيمة الافتراضية.
6

شغّل حاوية التجربة

docker run -d --name aizzak-runpod-test \
  --env-file ~/aizzak-runpod-test/test.env \
  -v aizzak-runpod-test-data:/workspace \
  -p 28080:80 \
  aizzak-runpod:staging-1
  • aizzak-runpod-test-data: قرص بيانات جديد وفارغ يمثّل قرص RunPod. لا علاقة له بأقراص المكدّس الحالي.
  • 28080: المنفذ الذي ستفتح منه التجربة على جهازك.
  • Docker على جهازك لا يصل إلى كرت الشاشة، فيعمل Ollama هنا على المعالج. هذا أبطأ لكنه يكفي للتأكد أن الصورة تقلع.
النتيجة المتوقعة: سطر طويل من الحروف والأرقام (رقم الحاوية).
7

راقب الإقلاع الأول

هذا الأمر يعرض الرسائل المهمة فقط ويتابعها لحظة بلحظة:

docker logs -f aizzak-runpod-test 2>&1 | grep --line-buffered -E "\[entrypoint\]|\[bootstrap\]|vault-start|⛔"

ستظهر هذه المراحل بالترتيب تقريباً:

  1. [entrypoint] initialising a new PostgreSQL 16 cluster
  2. vault-start: initialized; unseal key + root token recorded ثم vault-start: unsealed and ready
  3. [bootstrap] seeding Vault (KV v2 + Transit + AppRole)
  4. [bootstrap] minting the app's AppRole login
  5. [bootstrap] running migrations + grants (app.ops.provision)
  6. [bootstrap] pulling gemma3:1b: تحميل النموذج، وهي أطول مرحلة (عدة دقائق).
  7. [bootstrap] starting the API ثم [bootstrap] starting nginx
النتيجة المتوقعة: آخر سطر:
[bootstrap] ✅ boot complete -- http://localhost/health
الرابط في الرسالة لا يذكر المنفذ، والصحيح على جهازك هو 28080.

بعد ظهوره اضغط Ctrl+C لإيقاف المتابعة. هذا لا يوقف الحاوية.

إن ظهرت علامة ⛔توقّف الإقلاع. انسخ السطر الذي فيه ⛔ مع 20 سطراً قبله وأرسلها لي. لقراءة آخر 80 سطراً كاملة: 
docker logs aizzak-runpod-test 2>&1 | tail -80

تحقق أن كل الخدمات تعمل

docker exec aizzak-runpod-test supervisorctl -c /etc/supervisor/supervisord.conf status
النتيجة المتوقعة: كل الخدمات RUNNING، ما عدا bootstrap فحالته EXITED، وهذا طبيعي لأنه يعمل مرة واحدة ثم ينتهي. القائمة: app, bootstrap, embedding, minio, nginx, ollama, outbox-relay, postgres, qdrant, redis-cache, redis-stream, sshd, vault, worker.
curl -s http://localhost:28080/health
النتيجة المتوقعة: {"status":"ok"}
curl -s http://localhost:28080/health/ready
النتيجة المتوقعة: {"status":"ready"}
لماذا هذا يكفي لإثبات إصلاح Vaultالتطبيق يقرأ مفاتيح MinIO من Vault عند الإقلاع، ويرفض أن يعمل إن فشل الدخول. فوصول app إلى RUNNING وردّ /health يعنيان أن الأعطال الثلاثة أُصلحت.
9

جرّب الإقلاع الثاني

هذه الخطوة تثبت أن الحاوية تعود سليمة بعد إعادة التشغيل، كما سيحدث للـ Pod.

docker restart -t 60 aizzak-runpod-test

-t 60 يعطي الخدمات 60 ثانية لتُغلق بهدوء. بدونه يقتل Docker الحاوية بعد 10 ثوانٍ، فيُغلق Postgres وVault إغلاقاً مفاجئاً.

docker logs -f --since 2m aizzak-runpod-test 2>&1 | grep --line-buffered -E "\[entrypoint\]|\[bootstrap\]|vault-start|⛔"
النتيجة المتوقعة: هذه المرة تظهر رسائل مختلفة لأن البيانات موجودة، والإقلاع أسرع:
[entrypoint] existing PostgreSQL cluster found at /workspace/data/postgres -- leaving it alone vault-start: sealed; unsealing from the recorded init material at ... [bootstrap] gemma3:1b already present [bootstrap] ✅ boot complete -- http://localhost/health

ثم اضغط Ctrl+C وأعد فحص الصحة:

curl -s http://localhost:28080/health/ready
النتيجة المتوقعة: {"status":"ready"}

أخبرني بالنتيجة

  • إن نجحت الخطوات 7 إلى 9: اكتب لي «نجحت التجربة» واترك الحاوية تعمل. سأشغّل عليها فحصاً أعمق لقاعدة البيانات وعزل المستأجرين وVault وMinIO، ثم ننتقل إلى الرفع.
  • إن فشلت خطوة: أرسل لي رقمها وما ظهر في الطرفية.

ارفع الصورة إلى Docker Hub

بعد نجاح التجربة فقط. استبدل USERNAME باسم حسابك في Docker Hub.

docker login
النتيجة المتوقعة: Login Succeeded.
docker tag aizzak-runpod:staging-1 USERNAME/aizzak-runpod:staging-1
docker push USERNAME/aizzak-runpod:staging-1
  • الرفع يأخذ وقتاً حسب حجم الصورة (الخطوة 4-أ) وسرعة الرفع عندك. إن انقطع فأعد الأمر، فهو يكمل الطبقات الناقصة فقط.
  • المستودع في Docker Hub يكون عاماً عادةً. هذا مقبول هنا لأن الكود عام أصلاً على GitHub، والصورة لا تحمل أسراراً (الخطوة 4-ب).
  • عند أي تحديث لاحق استخدم وسماً جديداً (staging-2، staging-3، ...) ولا تُعِد استخدام وسم قديم، لأن RunPod قد يستمر في استخدام النسخة المخزّنة عنده.
النتيجة المتوقعة: آخر سطر يبدأ بـ staging-1: digest: sha256:. أرسل لي اسم المستخدم لأُكمل إعداد الـ Pod.

نظّف التجربة (بعد أن أنتهي من الفحص الأعمق)

docker stop -t 60 aizzak-runpod-test
docker rm aizzak-runpod-test
docker volume rm aizzak-runpod-test-data
rm -rf ~/aizzak-runpod-test
احذف بالاسم فقط لا تستخدم docker volume prune ولا docker system prune، فهما يحذفان أقراص المكدّس الحالي أيضاً. الصورة نفسها لا تحذفها، فقد نحتاجها.
