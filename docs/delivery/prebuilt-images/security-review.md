## قائمة الفحص
- [x] **المصادقة والصلاحيات:** لا مسار HTTP جديد. سطح التشغيل في CI: `on: push: tags: ["v*"]` وحده، بلا `pull_request` ولا `pull_request_target` ولا `workflow_dispatch`، فلا يصل fork إلى السرّ. `permissions: contents: read` على مستوى الملفّ. شرط `github.repository == 'anastawahia/aizzak'` على `preflight`، والوظيفتان التاليتان تتبعانه عبر `needs`. الثقة الفعليّة = «من يملك دفع وسم `v*`» (انظر S‑2).
- [x] **عزل المستأجرين:** لا ينطبق؛ لا استعلام ولا مستودع بيانات جديد، ولا شيفرة في `src/`.
- [x] **التحقّق من المدخلات (حقن الأوامر/السكربت):**
  - لا `${{ … }}` داخل أيّ `run:`. الوسم يصل عبر متغيّر البيئة `GITHUB_REF_NAME` مقتبساً (`"${GITHUB_REF_NAME#v}"`)، لا عبر تعبير.
  - السكربت يطابق الرقم مع `^20[0-9]{2}\.(1[0-2]|[1-9])\.[1-9][0-9]*$` قبل أيّ استعمال (`build-push.sh:64,275`).
  - أسماء مراجع git لا تقبل `:` ولا سطراً جديداً، فطباعة وسمٍ مرفوضٍ في رسالة الخطأ لا تحقن أوامر workflow (`::…::`).
  - كلّ المتغيّرات في السكربت مقتبسة، ولا `eval`. رابط `curl` ثابت (`build-push.sh:63`)، فلا SSRF.
- [x] **لا أسرار في الشيفرة أو السجلّات:**
  - الأسرار تُمرَّر تحت `env:` فقط، والدخول بـ`--password-stdin` (`release.yml:132-138`). لا `set -x` في السكربت، ولا يأخذ السكربت أيّ اعتماد. خطوة «Registry secrets are set» تطبع الأسماء لا القيم.
  - `docker logout` تحت `if: always()` (`release.yml:167-169`).
  - `.env.example` يحمل أسطراً معلّقة بقيم أمثلة (`anastawahia/aizzak`، `app-2026.10.1`)، لا قيمة سرّيّة.
  - الوثائق لا تحمل مفاتيح، وتطلب مفتاح Docker Hub بصلاحيّة **Read & Write بلا Delete** في بيئة `release` (`docs/stack-commands.md:551`).
  - فحص الأنماط على الفرق كلّه (`dckr_pat_`، `ghp_`، `github_pat_`، `AKIA…`، `-----BEGIN`، `hvs.`، JWT، سلاسل عالية الإنتروبيا): لا شيء. التطابق الوحيد نمطٌ داخل اختبار (`tests/unit/test_prebuilt_images_docs.py:83`).
  - **`gitleaks` و`trufflehog` غير مثبّتين** على هذا المضيف، ولا `shellcheck` ولا `actionlint` ولا `zizmor`. الفحص يدويّ بـ`git diff | grep` فقط.
- [x] **ما تحمله الصور (خطر نشرها عامّةً):**
  - `.dockerignore` يستبعد `.env` و`.env.*` و`deploy/load/accounts.json|tokens.json|include-workspaces.txt` و`deploy/nginx/certs/`.
  - في ملفّي Dockerfile، كلّ أمر `COPY` يسمّي مساراتٍ متعقَّبة صراحةً، ولا `COPY . .`.
  - `git status --ignored` على مسارات `COPY` كلّها لا يُظهر أيّ ملفٍّ مُتجاهَل، فلا يدخل سرٌّ محلّيٌّ صورةً تُبنى على جهاز المالك في مسار الطوارئ.
  - النتيجة: الصورتان لا تحملان إلّا ما في المستودع العامّ أصلاً، مع نموذج تضمينٍ عامّ.
- [x] **رسائل الخطأ:** تطبع رمز HTTP واسم المستودع والوسم ونصّ خطأ `imagetools`، ولا اعتماد فيها.
- [x] **التبعيات الجديدة:** لا حزمة Python جديدة، فلم يُشغَّل `pip-audit` (لا تغيير يُدقَّق). الـaction الجديدة الوحيدة `actions/upload-artifact@v4` رسميّةٌ من GitHub، ولا action من طرفٍ ثالث (D‑9). لكنّ التثبيت بوسمٍ لا بـSHA (S‑3).
- [~] **سلامة السجلّ وسلسلة التوريد:** حارس الخصوصيّة لا يفشل مغلقاً إن لم يوجد المستودع (S‑1). الخادم يسحب بوسمٍ قابلٍ للتغيير (S‑4). المساحة `aizzak` غير محجوزة (R‑3، خطرٌ قبله المالك).
- [x] **رفع الملفّات/الروابط الخارجية:** لا ينطبق.
- [x] **حدود المعدّل:** لا ينطبق؛ `concurrency: release` بلا إلغاء يمنع إصدارين متوازيين.

## قبل أوّل وسم `v*` (شروطٌ على المالك، لا تحجب الدمج)
1. Docker Hub: *Default repository privacy = Private*، ثمّ إنشاء `anastawahia/aizzak` **خاصّاً** (S‑1).
2. Docker Hub: مفتاح Personal Access Token بصلاحيّة Read & Write بلا Delete، وتفعيل *Immutable tags* للنمطين `app-*` و`embedding-*` إن أُتيح (S‑4).
3. GitHub: إنشاء البيئة `release` بقاعدة وسوم `v*` وبالسرَّين **أسرارَ بيئة**، وtag ruleset على `v*` (S‑2).
4. اختياريّ ورخيص: حجز المساحة `aizzak` على Docker Hub (S‑5 / R‑3).
