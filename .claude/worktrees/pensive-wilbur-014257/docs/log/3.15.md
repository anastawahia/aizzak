## 3.15 ما بُني — الموجة 2: محوّلات المجموعة (أ) `workspace`+`access`+`credentials` (SQL + هجرات + RLS حيّة)

**النطاق المقصود:** ثاني موجات المحوّلات على نمط §3.14 المُثبَت. نُفِّذت بالسلسلة **📐 architect → 🛠️ implementer (واحد متسلسل، بوابات بعد كل وحدة) → تدقيق**. ⚠️ **انحراف تشغيلي موثَّق:** وكيل ✅ verifier الخلفي قُتل بحدّ جلسة API فور انطلاقه (نفس حادثة §3.13)؛ فأجرى **المُنسِّق التدقيق بنفسه داخل الجلسة** بنفس قائمة الفحوص وبأدلة فعلية (بوابات + مجسّات psql حيّة + مطابقة توقيعات + تدقيق mtime) — **PASS**. `alembic.ini` هيّأه المُنسِّق قبل الإطلاق (الملف المشترك).

| الوحدة | المحوّل | خصوصياته |
|---|---|---|
| `workspace` | `SqlWorkspaceRepository` + `SqlUserRepository` (جدولان على `MetaData` واحد) | **`workspaces` بلا RLS** (جدول جذر المستأجر — `01 §3`): شرط `id = :ctx_ws` في `get`/`save` **هو حدّ العزل كاملاً** (لا شرط على `add` — لا صفّ يُرشَّح عند INSERT، موثَّق)؛ `SqlUserRepository` يُحقَن بمصنعَين: `tenant_session` للكتابة و**`platform_session` لـ`get_by_firebase_uid` حصراً** |
| `access` | `SqlRoleAssignmentRepository` | تجميعة إنشاء/حذف: **بلا `version`/`updated_at`/`save`/مشغّل**؛ `remove` صامت عند 0 صفوف؛ `count_by_role` يخدم INV‑A1 |
| `credentials` | `SqlCredentialRepository` | `CipherRef` ↔ عمودان (`ciphertext_ref`+`key_id`)؛ `find_active` يتفرّع على النطاق (user: صفوف المستأجر / platform: `workspace_id IS NULL` عبر سياسة `01 §3.1`)؛ `get` **مستأجري صارم** (لا يعيد صفوف المنصّة — R7، متعمَّد رغم أن الـfake الوحدوي أوسع) |

**سياسة الحارس الأمنية الجديدة (R1 — القرار المعماري الأبرز):** `get_by_firebase_uid` يعمل **قبل وجود سياق مستأجر** (JIT). سياسة «غياب السياق» **مرفوضة** (تسرّب كل المستخدمين في نمط السلسلة الفارغة المُصلَّب ضدّه)، ومفتاح‑الصفّ مستحيل (لا صفّ منصّة مشترك). المعتمد: GUC صريح **`app.platform_read='on'`** لا يضبطه إلا `PlatformSessionFactory` الجديد في `persistence/rls.py` (مستهلكه الشرعي الوحيد `get_by_firebase_uid`؛ أي مستهلك جديد = بند مراجعة أمنية):
```sql
CREATE POLICY users_platform_read ON workspace.users
  FOR SELECT USING (current_setting('app.platform_read', true) = 'on');
```
**مجسّات حيّة (كـ`app_rw`، أثبتها التدقيق):** بلا GUC ⇒ 0 · GUC فارغ بلا حارس ⇒ 0 **بلا خطأ** · الحارس وحده ⇒ قراءة عابرة (مسار JIT) · **الحارس لا يمنح كتابة** (INSERT ⇒ رفض RLS + ROLLBACK، لا شيء كُتب) · سياق سليم ⇒ الصفّ.

**قرارات مقرَّة أخرى:** **R4** فهرس إضافي `uq_cred_active_user UNIQUE (workspace_id, provider) WHERE status='active' AND scope='user'` — انحراف موثَّق عن `01 §2.3` يحوّل سباق TOCTOU «مفتاحين نشطين» إلى 23505→409 (**توصية مزامنة الوثيقة معلّقة**) · **R5** تعديل `ProvisionUserOnFirstLogin` المجمّدة (ينفّذ قرار §5‑7/N3): التقاط `ConflictError` حول `users.add` فقط → إعادة قراءة بالمفتاح الطبيعي → `created=False`؛ **يتيمة workspace للخاسر مقبولة v1** (حتى UoW نطاق‑الطلب) + اختبار وحدة لفرع السباق · **R3** بذر مفاتيح المنصّة إنتاجياً مؤجَّل لطور التشغيل (الاختبارات تبذر كمالك بمفتاح `NO FORCE`/`FORCE` في `try/finally`).

**الاختبارات:** ‏+34 (اختبار سباق وحدوي + **33 تكامل حيّاً**: ‏12 workspace [منها fail‑safe السلسلة الفارغة وسباق JIT] · 11 credentials [منها رؤية مفتاح المنصّة من مستأجرَين مع بقاء عزل صفوفهما، و409 عبر `AddUserCredential` فوق المحوّل الحقيقي] · 10 access). علّة FK حقيقية اصطادها المنفّذ في مثبّتاته (مستخدم بلا workspace أب) أُصلحت في الاختبارات لا المحوّل.

**بوابات الموجة (أعادها المُنسِّق):** ruff format ‏318 · ruff ✓ · mypy ‏278 (الأدلة كانت stubs محسوبة) · lint‑imports **8/0** · junit ‏**642** (‏0 فشل، 1 متخطّى قديم) · تكامل ‏**41/41** (8 media + 33 جديدة). مطابقة DDL حيّة: 5 سياسات بالضبط · أعلام RLS (الثلاثة ENABLE+FORCE و`workspaces` بلا) · الفهارس السبعة · مشغّلات touch الثلاثة (ولا شيء على `access`). تدقيق mtime: 17 ملفاً = اتحاد قائمتَي المُنسِّق والمنفّذ بالضبط.
