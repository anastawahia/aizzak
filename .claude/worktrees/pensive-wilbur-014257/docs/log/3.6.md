## 3.6 ما بُني — المرحلة 3 مجموعة (أ): وحدات التمكين والأمان

ثلاث وحدات بالقالب السداسي، **الشريحة النقية فقط** (Domain → Ports → Application + اختبارات وحدة فوق منافذ مزيّفة). **المحوّلات (`adapters/sql_repository.py`) + الهجرات + RLS مؤجّلة لطور البنية** (تحتاج Docker/Postgres) — نفس نمط الطور: الكود النقي يمرّ البوابات الخمس فوراً.

| الوحدة | الملفات | يحقّق | أبرز التفاصيل |
|---|---|---|---|
| `workspace` | domain(errors·value_objects·entities·events) · ports/repository · application/use_cases + اختباران | `06 §1` · `01 §2.1` · INV‑W1/W2 | `Workspace`·`User`؛ JIT provisioning؛ `version` تفاؤلي يرفعه الـrepo عند `save`؛ **`User.id` UUIDv7 منصّي + `firebase_uid` مفتاح بحث مستقل** (حسم N1 — `get_by_firebase_uid`) |
| `access` | domain(value_objects[RoleCatalog]·entities·events) · ports/repository·inbound · application/use_cases + اختباران | `06 §2` · `05 §1` · INV‑A1/A3 · D‑24 | `RoleCatalog` ثابت بالكود (05 §1.3 حرفياً)؛ `AuthorizationService` وارد؛ `is_allowed` نقي؛ `platform_admin` غير قابل للإسناد عبر API |
| `credentials` | domain(errors·value_objects·entities·events) · ports/repository·inbound · application/use_cases + اختباران | `06 §3` · `05 §3` · `02 §1.9/§2/§3.5` · INV‑C1/C2 · D‑16 | `Credential` AR؛ التشفير عبر `SecretsProvider.encrypt/decrypt` (Transit `tenant-secrets`)؛ `CredentialResolver` وارد (user→platform، **بلا fallback بين مزوّدين**)؛ `ResolvedKey` داخلي فقط |

**تفاصيل مفتاحية:**
- **§5.1 محسوم:** لا كِرنل نطاق مشترك — نطاق كل وحدة مكتفٍ ذاتياً (stdlib فقط)؛ الأخطاء النطاقية محلية وتُترجَم إلى `framework/errors` عند حدّ التطبيق. **صفر تعديل على `.importlinter`** (عقد «نقاء النطاق» محفوظ — تحقّق `lint-imports`).
- **`credentials` والتشفير:** المفتاح الخام لا يُخزَّن أبداً؛ يُشفَّر فور الاستلام إلى `CipherRef` (ciphertext + `key_name`). `ResolveCredential` يفكّ التعمية داخل الحدود فقط ويعيد `ResolvedKey` للمُنسِّق (لا يعبر API — INV‑C2). `AddUserCredential` يرفض مفتاحاً نشطاً مكرّراً لنفس المزوّد (**409**). `label` افتراضي مقنّع `****<آخر 4>`.
- **⚠️ قرار مؤجَّل للمحوّل:** `find_active(scope=platform)` يقرأ صفوف `workspace_id IS NULL` عابرة للمستأجر — يتطلّب **سياسة RLS تسمح بقراءة صفوف المنصّة (NULL) لكل المستأجرين** عند بناء محوّل `credentials` وهجرته (`01 §2.3` · `05 §3`). الشريحة النقية تُجرّده خلف `CredentialRepository`.
- **بذرة platform (مفتوح):** أُسقِط طابق env seed (لا `SERVICE_API_KEY`) — إن بقيت تجربة ilmu مطلوبة فتحتاج صفّ Credential platform مبذوراً صراحةً (`refs/credentials-oauth-jobs.md §5‑4`).
